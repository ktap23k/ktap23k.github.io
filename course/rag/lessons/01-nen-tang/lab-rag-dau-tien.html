Lab: dựng RAG đầu tiên trong 60 dòng Python

Không framework, không vector database — chỉ numpy, một embedding model chạy local và LLM bạn đang dùng. Mục tiêu là thấy rõ từng bánh răng trước khi thay chúng bằng bản xịn hơn.

Mục tiêu bài học

  • Cài đặt môi trường và chuẩn bị bộ tài liệu mẫu.
  • Viết đủ 4 bước: chunk → embed → search → generate.
  • Quan sát các lỗi điển hình của Naive RAG để hiểu vì sao cần các module sau.

2. Toàn bộ mã nguồn

# rag.py
from pathlib import Path
import numpy as np
from sentence_transformers import SentenceTransformer
from llm import call_llm

model = SentenceTransformer("intfloat/multilingual-e5-small")  # nhỏ, có tiếng Việt

def embed(texts: list[str], kind: str) -> np.ndarray:
    # E5 là model bất đối xứng: câu hỏi và đoạn văn cần prefix khác nhau
    return model.encode([f"{kind}: {t}" for t in texts], normalize_embeddings=True)

def chunk_text(text: str, max_chars: int = 800) -> list[str]:
    """Gom các đoạn văn liền nhau thành chunk không quá max_chars ký tự."""
    chunks, current = [], ""
    for para in (p.strip() for p in text.split("\n\n")):
        if current and len(current) + len(para) > max_chars:
            chunks.append(current)
            current = ""
        current = f"{current}\n\n{para}".strip()
    return chunks + [current] if current else chunks

class TinyIndex:
    def __init__(self):
        self.chunks: list[tuple[str, str]] = []   # (nguồn, nội dung)
        self.vectors = np.empty((0, 384), dtype=np.float32)

    def add(self, source: str, text: str):
        pieces = chunk_text(text)
        self.chunks += [(source, p) for p in pieces]
        self.vectors = np.vstack([self.vectors, embed(pieces, "passage")])

    def search(self, query: str, k: int = 4):
        scores = self.vectors @ embed([query], "query")[0]   # cosine vì đã chuẩn hoá
        best = np.argsort(-scores)[:k]
        return [(*self.chunks[i], float(scores[i])) for i in best]

PROMPT = """Trả lời câu hỏi CHỈ dựa trên các đoạn tài liệu dưới đây.
Nếu tài liệu không đủ thông tin, trả lời: "Mình không tìm thấy thông tin này trong tài liệu."
Ghi nguồn dạng [1], [2] ngay sau ý sử dụng nó.

{context}

Câu hỏi: {question}"""

def answer(index: TinyIndex, question: str) -> str:
    hits = index.search(question)
    context = "\n\n".join(f"[{i}] ({src})\n{text}" for i, (src, text, _) in enumerate(hits, 1))
    return call_llm(PROMPT.format(context=context, question=question))

if __name__ == "__main__":
    index = TinyIndex()
    for path in sorted(Path("docs").glob("*.md")):
        index.add(path.name, path.read_text(encoding="utf-8"))
    print(f"Đã index {len(index.chunks)} chunk.")
    while question := input("\nHỏi (Enter để thoát): ").strip():
        for src, text, score in index.search(question):
            print(f"  {score:.3f}  {src}: {text[:70]!r}")
        print("\n" + answer(index, question))
Số 384 ở đâu ra?

Đó là số chiều vector của multilingual-e5-small. Đổi model thì đổi theo — hoặc lấy tự động bằng model.get_sentence_embedding_dimension().

3. Đọc hiểu từng phần

  • chunk_text: gom đoạn văn đến khi chạm ngưỡng 800 ký tự. Thô sơ nhưng tôn trọng ranh giới đoạn — tốt hơn cắt cứng mỗi N ký tự.
  • embed: chuẩn hoá vector (normalize_embeddings=True) nên tích vô hướng chính là cosine.
  • search: "vector database" phiên bản nhỏ nhất — nhân ma trận rồi sắp xếp. Với vài chục nghìn chunk, phép nhân này chỉ mất vài mili-giây; phần tốn thời gian nhất là embed câu hỏi.
  • PROMPT: ba chỉ dẫn quan trọng nhất — chỉ dùng context, được phép nói không biết, và dẫn nguồn.

4. Thử nghiệm và quan sát

Hãy thử lần lượt các loại câu hỏi sau và ghi lại kết quả. Đây chính là cách "cảm" được điểm yếu của Naive RAG:

  1. Câu hỏi diễn đạt khác tài liệu ("được nghỉ mấy hôm?"): thường vẫn tìm đúng — sức mạnh của embedding.
  2. Câu hỏi có mã số, tên riêng ("điều 12 nói gì?"): hay tìm sai — cần hybrid search (bài 3.1).
  3. Câu hỏi không có trong tài liệu: model có nói "không tìm thấy" không, hay vẫn bịa?
  4. Câu hỏi cần tổng hợp hai tài liệu: top-4 có đủ cả hai nguồn không?
  5. Câu hỏi gõ không dấu ("nghi phep nam"): điểm số giảm thế nào?

Tóm tắt

  • Một RAG hoàn chỉnh chỉ cần 4 bước: chunk, embed, search, generate.
  • Tìm kiếm vector ở quy mô nhỏ chỉ là một phép nhân ma trận.
  • Prompt phải cho phép model nói "không biết" và bắt buộc dẫn nguồn.
  • Naive RAG yếu với mã số, câu hỏi đa nguồn và câu hỏi không dấu — động lực cho các module sau.

Kiểm tra nhanh

Điều gì xảy ra nếu bỏ prefix "query: " khi embed câu hỏi với model E5?

Code vẫn chạy, nhưng câu hỏi được mã hoá như một đoạn văn bình thường nên chất lượng tìm kiếm giảm — một lỗi "im lặng" khó phát hiện nếu không có bộ đánh giá.

Khi nào cách tìm kiếm bằng numpy trong bài này không còn phù hợp?

Khi kho lên hàng triệu chunk (tốn RAM, quét toàn bộ chậm), khi cần lọc metadata, cập nhật/xoá từng chunk hoặc nhiều tiến trình dùng chung — lúc đó cần vector database với chỉ mục ANN (bài 2.4).

Vì sao prompt đánh số [1], [2] cho từng đoạn context?

Để model trích dẫn được và để code kiểm tra/hiển thị nguồn: mỗi số ánh xạ về file gốc, người dùng bấm vào là xem được đoạn tài liệu.
